1.Redis 缓存穿透
当访问数据库不存在的数据时，会导致Redis失效
解决方法： a、 缓存空数据，缺陷：占用资源可能较多，若数据库修改，后续可能出现数据不一致
         b、 布隆过滤器， 位图， 利用哈希算法计算元素是否存在， 空间占用少，但可能存在误判， 位图占用空间越大，误判率越低

2. 什么是缓存击穿
给某一个key设置了过期时间，当key的过期时间到了，在这个时间点恰好有大量该key的并发请求过来，这些并发请求可能会把DB压垮
解决： a、 互斥锁： 强一致，性能差
	  b、 逻辑过期： 高可用，性能优，不能保证数据绝对一致
3. 什么是缓存雪崩
当大量的key同时失效 或者 Redis宕机了，导致大量请求到达数据库，带来巨大压力
a、 给不同的key的TTL设置随机值，防止key同时失效
b、 利用Redis集群提高服务的可用性  比如哨兵模式、集群模式
c、 给缓存业务添加降级限流策略  nginx ， springcloud gateway  （降级可作为系统的保底策略，适用于穿透、击穿、雪崩）
d、 给业务添加多级缓存，为Redis加保险 Guava 和 Caffeine

4. mysql数据如何与Redis保持一致的（双写一致性）
对于 实时性没有那么高的业务，采用异步的方案实现同步数据
a、 通过MQ中间件，更新数据之后，通知缓存删除
b、 利用canal中间件，不需要修改业务代码，伪装成mysql的一个从节点，canal通过读取binlog数据来更新缓存
对于 需要实时同步数据的业务，为保证数据的强一致，采用Redisson 的读写锁来保证数据的同步
a、 共享锁：读锁readLock，加锁之后，其他线程可共享读操作
b、 排他锁：写锁writeLock， 也叫独占锁， 加锁之后，阻塞其他线程的读写操作
