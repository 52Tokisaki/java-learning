1. 了解过索引吗（什么是索引）
索引（index）是帮助MYSQL高效获取数据的数据结构（有序）
提高数据的检索效率，降低数据库的IO成本（不需要全表扫描）
通过索引对数据进行排序，降低数据排序的成本，降低CPU的消耗

2. 索引的底层数据结构
MySQL的InnoDB引擎采用的B+树数据结构存储索引
阶数更多，路径更短
磁盘读写B+树代价更低，非叶子节点仅存储指针，叶子节点存储数据
B+树便于扫库和区间查询，叶子节点是一个双向链表

3. 聚簇索引 & 非聚簇索引
聚簇索引： 数据和索引放在一块，B+树的叶子节点保存了整行数据，有且只有一个
非聚簇索引（二级索引）： 数据和索引分开存储， B+树的叶子节点保存对应主键， 可以有多个

4. 什么是回表查询
通过二级索引找到对应的主键值，再到聚簇索引中找到整行数据，这个过程就是回表查询

5. 什么是覆盖索引
覆盖索引是指查询使用了索引，返回的列必须在索引中能够全部找到
使用id查询，直接走聚簇索引查询，一次索引扫描，直接返回数据，性能高
如果返回的列中没有创建索引，可能触发回表查询，因此尽量避免使用select *

6. MySQL超大分页查询怎么处理
数据量比较大时， limit分页查询，需要对数据进行排序，效率低
可以使用覆盖索引 + 子查询
select * from table1 t , (select id from table1 order by id limit 9000000, 10)  a where t.id = a.id;

10. 事务的特性（ACID） 原子性（Atomicity）、一致性（Consistency）、隔离性（Isolation）、持久性（Durability）
以转账为例
a、 原子性： 事务是一个不可分割的工作单位，事务中的操作要么都完成，要么都不完成，A向B转账500，要么转成功，要么转失败
b、 一致性： 事务必须使数据库从一个一致性状态变换到另一个一致性状态， A扣除500，B增加500，数据库的一致性状态
c、 隔离性： 事务的执行是相互隔离的，一个事务的中间状态对其他事务是不可见的 不受其他事务干扰
d、 持久性： 事务一旦完成，其结果就是永久性的，即使系统发生故障也不会丢失 事务提交后，数据持久化（落盘操作）

11. 并发事务带来哪些问题，如何解决，MYSQL的默认隔离级别
a、并发事务问题：
脏读： 一个事务读到另一个事务还没有提交的数据
不可重复读： 一个事务先后读取同一条记录，但两次读取的数据不同
幻读： 一个事务按照条件查询，没有对应的数据行，但是在插入数据时，又发现这行数据已经存在，好像出现了“幻影”
b、隔离级别
READ UNCOMMITTED 未提交读 不能解决脏读、不可重复读、幻读
READ COMMITTED 读已提交   不能解决不可重复读、幻读
REPEATABLE READ 可重复读  不能解决幻读
SERIALIZABLE 串行化       均能解决，但是效率最低

12. undo log 和 redo log的区别
redo log 记录的是数据页的物理变化，服务宕机可用来同步数据
undo log 记录的是逻辑日志，当事务回滚时，通过逆操作回复原来的数据
redo log 保证了事务的持久性，undo log 保证了事务的原子性和一致性

13. 事务隔离性是如何保证的（MVCC） Multiple Version Concurrency Control
MySQL中多版本并发控制，指维护一个数据的多个版本，使得读写操作没有冲突
	a、 隐藏字段
	trx_id（事务id）： 记录每一次操作的事务id，是自增的
	roll_pointer（回滚指针）： 指向上一个版本的事务版本记录地址
	b、 undo log
	回滚日志，存储老版本数据
	版本链：  多个事务并行操作某一行记录，记录不同事务修改数据的版本，通过roll_pointer指针形成一个链表
	c、readView 解决的是一个事务查询选择版本的问题
	根据readView的匹配规则和当前的一些事务id判断该访问哪个版本的数据
	不同隔离级别快照读是不一样的，最终访问的结果不一样
	RC： 每一次执行快照读时生成ReadView
	RR： 仅在事务中第一次执行快照时生成ReadView，后续复用

14. MYSQl主从同步原理
MYSQL主从复制的核心就是二进制日志binlog（DDL语句 数据定义语言 和 DML语句 数据操纵语言）
a、主库在事务提交时，会把数据变更记录在二级制日志文件binlog中
b、从库读取主库的二进制日志文件binlog，写入到从库的中继日志RelayLog中
c、从库重做中继日志中的事件，将改变反映它自己的数据

15. MYSQl分库分表
业务介绍： 根据自己的项目，想一个数据量较大的业务（请求数多或者业务积累大）；达到了什么样的量级（单表1000万活超过20G）
具体拆分策略
a、水平分库： 将一个库的数据拆分到多个库中，解决海量数据存储和高并发的问题        sharding-sphere， mycat
b、水平分表： 解决单表存储和性能问题
c、垂直分库： 根据业务拆分，高并发下提高磁盘IO和网络连接数
d、垂直分表： 冷热数据分离，多表互不影响
